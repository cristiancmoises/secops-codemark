# Contributing to SecOps Codemark

Use Python 3.10 or newer. Base runtime code uses the standard library; hybrid signing requires OpenSSL 3.5+, encrypted bundles require native Zupt 5.2.10+, and the GUI is optional. Preserve the mandatory dual-signature policy, independent key pins, exact snapshot-byte binding and expected-checkpoint checks. Prefer small, reviewable changes with a synthetic reproducer for defects.

## Validate a change

```sh
python3 -m unittest discover -s tests -v
python3 scripts/build.py --output /tmp/codemark-development-package
python3 -I /tmp/codemark-development-package/codemark.pyz self-test --json
```

Use a new output directory for each build. For a strict website check, prepare the declared downloads first using the [release workflow](docs/en/releasing.md); a package-free preview does not qualify release downloads.

Read failures and optional-tool skips. A skip does not qualify a component. Package isolation should be checked outside the source checkout. Creating a genuine source release additionally requires installed `zupt` and `python3 scripts/build.py --output /a/new/output --archive`; inspect and test the archive before publication.

Keep source byte preservation, protected prologues, resource ceilings, known exclusions, metadata validation, signature pinning, report durability, and rollback behavior intact. Do not disable tests or weaken controls to get a passing build. Keep test keys ephemeral and project fixtures synthetic.

## Documentation and website

Update both `README.md` and `README.pt-BR.md` and relevant pages in `docs/en` and `docs/pt-BR` when changing user-visible behavior. The site is generated by `scripts/build_site.py` from those documents, local assets, and `website/data/release.json`.

The published site is plain HTML, CSS, and SVG. Do not add JavaScript, analytics, external fonts, or remote asset dependencies. Preserve semantic landmarks, keyboard navigation, visible focus, readable contrast, narrow-screen layouts, and reduced-motion support.

## Evidence and releases

Record the actual revision, environment, commands, results, dates, and limitations. Keep pending checks pending until run. Distinguish agent review from an external audit. Preserve historical records without presenting them as current qualification.

Public source and archives must exclude task prompts, agent execution instructions, private keys, tokens, private histories, and unrelated user data. Do not put personal credentials in tests. A checksum detects differences against a trusted reference; it does not authenticate the publisher alone.

## License and review

Contributions must be compatible with GPL-3.0-or-later. Preserve existing notices and document the provenance and license of imported material. Describe the concrete behavior changed and the validation performed. Report sensitive defects according to [SECURITY.md](SECURITY.md).

## Português brasileiro

Use Python 3.10+, fixtures sintéticas e chaves efêmeras. Execute os comandos acima em uma saída nova e registre falhas e ausências. Prepare os downloads antes de `--check`, conforme o [fluxo de lançamento](docs/pt-BR/releasing.md). Preserve bytes, limites, validação de metadados, pinagem de chaves e rollback. Atualize a documentação em inglês e português. Não publique prompts privados, instruções de execução, credenciais ou históricos. As contribuições precisam ser compatíveis com GPL-3.0-or-later.
